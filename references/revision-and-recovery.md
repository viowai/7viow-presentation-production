# Revision and recovery

Read for manual edits, chapter work, uncertain operations or recovery. Preserve the latest applicable authorization, current review level and current original. Resume the affected level in confirmation-workflow.md; a repair does not restart every prior stage or approve a later one.

## Diagnose the requested dimension

Locate the observation, its evidence, effect on the reader, and permitted repair scope. Content, visual hierarchy, missing assets and native-file errors require different work. A finding-only request returns located findings and desired reading results; it does not specify a new layout or silently edit text.

Interpret a manual change at its actual level. A sharper title may leave supporting prose intact. A changed service concept may affect examples, timelines and later conclusions. Protect unaffected accepted text and deliberate voice. Delegate the semantic decision to the content owner when necessary; do not solve every dense page by shortening its copy.

## Continue chapters

For the next unit, use its current original, accepted anchors, current feedback and relevant neighboring passages. Complete the actual revision and carry forward its dependencies. On integration, inspect the previous ending and next opening, terminology, duplicated explanations, moved material and references. Repair joins without rewriting intact chapter content.

Integrate the real native files, then check slide order, visible/hidden status, numbering, media and the applicable export. A collection of chapter previews is not the requested complete deck.

## Recovery decisions

- **Same filename, wrong return:** compare expected edits and actual content. Keep an unverified file separate from the accepted original; retrieve the correct return before integration.
- **Timeout after a possible write:** read the current state before retrying. Retry only the part that is demonstrably incomplete. Record unresolved state if readback is unavailable.
- **Missing native output:** preserve available text or previews, state the editable-delivery gap, and seek an authorized real export route. A screenshot deck is not an equivalent editable result.
- **Missing asset or tool:** use an available alternative only if it meets the same requested outcome. If the outcome must change, surface that choice instead of silently reducing quality.
- **Changed environment:** identify which prior evidence may no longer apply. Recheck affected behavior; retain unaffected evidence with its actual environment.
- **User stops:** preserve the current original, completed units, unchecked returns, permission boundary and exact next action. Do not create background continuation.

Do not repeat an identical failed action when its condition has not changed. Recovery does not authorize configuration changes, installation, restart, new accounts or a new user thread.
