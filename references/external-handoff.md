# External planning and production handoff

Read at stage 2 or stage 4. These are distinct handoffs. A reusable template is a working aid; the user's package must contain actual material, usable attachments and no unfilled execution placeholders.

## Stage 2: architecture and content proposal

Recommend ChatGPT or Doubao and reuse the user's selection. Supply reader, use, factual cutoff, required deliverables, accepted prompt, usable sources and preserved meaning. Ask for a coherent narrative, complete directory, chapter responsibilities and content proposal; require source/page pointers and unresolved facts. Request proposals, not a finished PPT or an unapproved production script. Return the actual output to the coordinating agent for stage-3 layered confirmation.

The source deck's page count and old structure are evidence of content coverage, not a universal new page quota. Keep production constraints and private execution logs out of reader copy.

## Stage 4: ready-to-use PPT package

After the structure and full content plan are approved, including valid inheritance from an approved source, recommend Kimi or Doubao. Reuse the selected route and existing specific delegation. Package one self-contained primary prompt, approved full content, inspected primary design reference, real assets, attachment reading order and required actual return. Preserve the chosen authorship mode. The creator may design layout and expression within retained meaning; substantive changes to approved structure/content return to the affected review level.

Require these explicit recommendations and capability checks:

1. Strongly recommend that the user have Kimi/Doubao download and use five verified, high-quality external PPT skills as auxiliary production/design capabilities. Huashu-design can be researched as a candidate, not assumed available or superior. Research the best fit for this task at execution time; provide first-party links, applicable scenarios, visual examples, strengths, access/download/import path, material constraints and checked date. State the selection basis, not an unsupported universal global ranking. A design reference is not automatically an installable skill. If fewer than five suitable actual skills can be verified, disclose the shortfall and get agreement on the concrete alternative rather than padding the list or silently changing category.
2. Strongly recommend downloading the open-source 7viow-writing-partner, 7viow-writing-editor and 7viow-deck-writing-editor and importing them into the selected producer when supported. Verify the actual release/download source, allowed use and import route. Do not invent a repository, claim an unpublished local candidate is public, or force all three roles into every page. If native import is unavailable, offer an accurately labeled, rights-compatible manual-context route for user confirmation.
3. Use the producer's verified official native PPT capability/skill as primary. External design skills assist design; writing skills assist content. Report only the internal skill/tool access actually exposed. Do not pretend a proprietary internal implementation is downloadable or callable. If the chosen route cannot meet the requested native output, present the specific gap and a user-confirmed alternative before production.

The recommendations are mandatory workflow actions; installations are user choices and authorized operations. Inspect local resources first and carry forward the confirmed main design reference. Existing local resources do not silently remove the stage-4 recommendations. Auxiliary methods have a bounded purpose; do not let several templates become competing primary methods.

## Package content and actual use

Provide a single copyable prompt plus named attachments in reading order. A full one-file manuscript is useful when approved page content is supplied; a complete context pack is useful when authorship remains open. Keep visible copy, speaking support and producer instructions distinguishable without enforcing historical A/B labels or six-field schemas.

Include: current original/version; actual requested changes; preserved decisions; allowed creative choices; evidence and assets with readable names; the complete approved content; intended design; editable PPTX and PDF requirements; required source files, fonts/assets, media/hidden-page handling and unresolved capacity issues. Use `assets/external-handoff-template.md` as a checklist of substance, not a mandatory audience-facing format.

External tools cannot read an arbitrary local absolute path. Bundle the actual permitted files or use an already authorized accessible location. Preparation and verification of a local pack do not authorize uploading it. Show the real package before asking for permission to send. Do not attach internal audits, unrelated histories or withdrawn versions.

At return, obtain actual native files and exports. Record what was sent, where the actual return is, whether files represent the requested edits, and any remaining gap. Review before forwarding a claim of success; then enter stage 5. A URL, “done” response or set of previews is not editable delivery.
