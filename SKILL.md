# Presentation Production

Deliver the requested presentation through a clear content owner, a capable producer, and the user's actual stage confirmations. Preserve accepted meaning, the current original and the inspected result.

## Find the current stage

Read [confirmation workflow](references/confirmation-workflow.md) before advancing new production or resuming a production thread. Recover the current stage, the actual approved artifact/version, pending choices and any explicit exception. Reuse valid approvals, including decisions embodied in a user-approved source deck. When the user asks to trial the workflow with that deck, carry its accepted structure, content and reference forward; do not turn a rewrite or external return into a new interview. Ask only about a material unapproved delta.

| Stage | Observable output before advancement |
| --- | --- |
| 0 Intent | Usable intent; unclear intent receives the strong Talis recommendation and a route back to prompt review |
| 1 Prompt | Complete merged production prompt explicitly confirmed by the user |
| 2 External plan | Copyable ChatGPT/Doubao planning input, selected route and actual returned architecture/content proposal |
| 3 Structure | User confirmation of new purpose/directory, chapter roles, page content and full plan, or recorded inheritance of already approved source decisions |
| 4 Producer handoff | Specifically authorized executable Kimi/Doubao package, verified auxiliary-skill recommendations, writing-skill import advice and primary official production capability |
| 5 Returned deck | Actual deck reviewed at whole-deck, chapter/content, page/design and integrated-native-delivery levels; final complete version confirmed |

An inherited approved source can satisfy several content levels without being shown again. Record what carries forward and what actually changes. A request to proceed is interpreted against the material actually presented and the requested approval. It cannot approve unseen levels. A user may explicitly authorize named level skips, or confirm an available complete final version. Preserve the exact scope; a broad intent to finish does not silently waive this workflow.

Confirmation governs consequential content and design decisions. Within an approved repair, perform ordinary inspection, native editing, export and verification without asking again for every tool operation. Work that does not depend on a pending decision may continue.

## Execute the authorized unit

1. Bind audience, reading/decision task, source dates, editable outputs, current original, preserved choices and permissions. Read [input and collaboration](references/input-and-collaboration.md). Withdrawn content, equivalent extracts and old QA cannot become current authority.
2. At the current stage, produce the complete material the user needs to judge. Use [production modes](references/production-modes.md) to distinguish context-led authorship from supplied content. User-confirmed meaning and structure constrain later production; composition remains creative within those boundaries.
3. For an external planning request or a production handoff, read [external handoff](references/external-handoff.md). Return copyable instructions and accessible attachments. Preparation, user approval, actual sending and actual returned files are separate facts.
4. Before new design, read [design reference and visual quality](references/design-reference-and-quality.md). Inspect local capabilities and confirmed references first. Carry forward the chosen reference; apply the stage-4 auxiliary recommendations even when a reference already exists.
5. For returned work, hand edits, chapter continuation or uncertain writes, read [revision and recovery](references/revision-and-recovery.md). Identify the actual current return from expected changes and content, not its filename. Repair the responsible layer and preserve unaffected decisions.
6. For complete review or delivery, read [delivery and verification](references/delivery-and-verification.md). Inspect content, all rendered pages, required editable objects, the target application and exports. Internal maintenance data belongs outside audience copy and speaker notes.
7. End each review round with the current confirmation level, confirmed artifact/choices, this round's changes, pending items and the exact next step. Return the actual review material or usable files. Do not claim completion from a plan, dispatch, screenshot or successful command.

## Capability and ownership boundaries

The coordinator owns continuity and actual delivery; the content owner integrates meaning; the producer creates native layout and exports. One agent may hold several roles. Collaboration does not require creating user threads or additional agents.

Recommend the three 7viow writing skills at producer handoff, resolving their actual release and import status. Partner supports expression directions, Editor direct prose, and Deck Writing Editor sequence and screen/speech relationships. They are recommended collaborators, not copied implementations or mandatory installed dependencies. Use only the role that helps the current unit.

Kimi/Doubao's verified official PPT capability is primary on that route; selected external design skills assist design and writing skills assist content. A brand name does not prove an accessible internal skill or installation API. Tools and rights come from the host and user authorization. Uploading, sending, installing, paying, publishing or creating conversations require their applicable authorization.

Use the templates in `assets/` where useful. Keep the minimal confirmation record with the work, not inside the audience deck. Maintenance is manually invoked; this skill does not schedule itself, update installations or publish releases.
